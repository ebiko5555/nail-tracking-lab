# NAIL TRACKING LAB

スマートフォンのカメラで片手の5指を追跡し、爪位置の推定精度を調べる独立した技術検証アプリ。TSUYAのファイル・コードは使用も変更もしない。正本はこのディレクトリの `src/`、ビルド済みの静的サイトは `deliverables/web/`。

**iPhone Chromeで試すURL：** https://ebiko5555.github.io/nail-tracking-lab/  
Chromeで開き「カメラ開始」→背面カメラを許可する。初回は手の認識モデルを約7.8 MB読み込むため、少し待つ。背面カメラを利用できない場合はエラーを表示する。

## 起動

Node.js 20.19以上を用意し、このディレクトリで次を実行する。アカウントや有料APIは不要。

```sh
npm install
npm run dev
```

PCでは表示された `http://localhost:5173/` を開く。初回はGoogleの公開Hand Landmarkerモデルをダウンロードするためインターネット接続が要る。処理するカメラ映像を送るAPIは実装していない。MediaPipeのWASMはアプリと同じ場所から読み込む。補正値だけが「保存」ボタンを押した時に `localStorage` に残る。固定フレーム画像と手動輪郭は一時メモリ上に置き、比較結果のJSONは「比較結果を保存」を押した時だけダウンロードする。JSONには画像を含めない。

本番用ファイルは `npm run build` で `deliverables/web/` に出力する。`npm run preview` でPC上の確認ができる。静的ファイルだけで動くためGitHub Pagesなどに配置できる。公開手順は [docs/publish.md](docs/publish.md) を参照。iPhoneのカメラ利用にはHTTPSが必要なので、PCの開発サーバーを同じWi-Fi上でHTTP接続する方法では動かない。無料の静的ホスティングへ配置するか、信頼済み証明書を用いたローカルHTTPS環境で確認する。

合成座標テストの `npm test` は、TypeScriptを直接読み込めるNode.js 24以上で実行する。ビルドとアプリ起動はNode.js 20.19以上でよい。

## 実験方法

1. 「カメラ開始」を押し、背面カメラの許可を与える。左右反転の初期値はオフ。
2. `LANDMARK` で21点、`NAIL POSITION` で推定輪郭、`NAIL OVERLAY` で5色の重ね描きを見る。
3. `DEBUG` で白の破線（補正前）と色付き線（補正後）、描画FPS、推論時間、描画時間、各指の状態・変動を比較する。
4. 指ごとに位置・幅・長さを調整する。保存操作をしない限り再起動後には残らない。
5. 「1フレーム固定」を押す。指を選び、爪の外周を順に3〜12点タップする。中心差と面積比で推定と手動輪郭を比較する。

「幾何品質」は関節点の配置に関する独自の目安であり、実際の爪検出確率ではない。近接や画面端では不明にする。追跡が切れると最大350 msだけ薄く保持し、その後消す。`held` は現在検出中という意味ではない。

## 現状

- 実装済み：PHASE 1の5指推定描画、PHASE 2の個別補正・One Euro Filter・補正前後比較・短時間保持、PHASE 3のモデル調査、PHASE 4の自動幾何テストと実機手順。
- 未実装：実際の爪輪郭を見つける専用AI、爪の3D面推定、WebGL描画、iPhone実機での性能実測。輪郭は楕円近似と手動指定のみ。
- 目標：描画30 FPS。実機での到達状況は未測定。推論は最低50 ms間隔に制限し、描画と別に計測する。端末が熱くなる場合はカメラを停止する。

## 変更してはいけないもの

TSUYAと `00_Core/`、旧Vault、エクスポート元データ。このアプリ内でも撮影画像を自動保存しない。
